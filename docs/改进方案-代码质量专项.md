## 改进 2：前端监听器泄漏治理

### 2.1 charts.js resize 监听进 dispose

- 现状：K线/环形/条形图各注册匿名 `window.addEventListener('resize', ...)`（charts.js:497,566,597），而 dispose 只移除 keydown（charts.js:536-537）→ 每选一只标的 +1 个永久监听，指向已 dispose 的实例
- 方案：三处改命名函数 `const onWinResize = () => chart.resize();`，dispose 中 `window.removeEventListener('resize', onWinResize)`（与 keydown 同处）；确认 `setSubSeries` 重建路径不复用监听（实例级 handler 随 dispose 一起释放）

### 2.2 favStar 改事件委托

- 现状：`favStar(code)`（common.js:96-110）每颗星注册 1 个 click + 1 个 window `fav-change` 监听，永不移除；列表/表格每次重绘重建全部星标（summary 筛选每击键 +50 个；每次 toggleFav 触发全部监听各自 `JSON.parse(localStorage)`）
- 方案：
  - `favStar(code)` 改为**纯渲染**：`<button class="fav-star" data-code="{code}">`，不含任何监听
  - 新增 `bindFavDelegation(container)`：容器级 click 委托（`e.target.closest('.fav-star')`，`stopPropagation` 语义保留）+ 一个 window `fav-change` 委托（只处理 `detail.code`，一次 `getFavs()` 更新该 code 全部星标）
  - 各视图 mount 时对列表容器绑定一次（容器常驻 → 有界）；重绘不产生新监听
- 涉及：common.js + 所有 `favStar` 调用视图（summaryView / historyLayout / compareView / scanView / recommendView，grep 定位）在 mount 处补一行绑定

### 2.3 attachSearchHistory 与视图清理通道

- 现状：`attachSearchHistory` 的 document click 监听每次挂载 +1（common.js:187）；app.js 失败重试路径（app.js:40-46）会重新 mount 造成叠加
- 方案：`attachSearchHistory` 返回 `dispose` 函数；`app.js` 的 `containers[name]` 增加 `cleanups: []` 字段，mount 返回的 dispose 收进数组，失败重试前先执行旧 cleanups（顺带解决 L6 的重复挂载叠加）

## 改进 3：renderTable 字符串列排序修复

- 现状：默认比较器 `(a,b) => a-b`（common.js:543-544），字符串相减 = NaN 被当 0 → 名称/行业/类型/分组等文本列表头点击**静默无效果**（受影响：backtestView.js:9 名称、scanView.js:136-144 名称/类型/分组、recommendView.js:267-268、historyLayout.js:486-493 成分股表；summaryView 有显式 `localeCompare` cmp 未受影响——反证默认比较器有缺陷）
- 方案（一个函数改动，保持 null 排最前语义与现值一致）：

```js
const defaultCmp = (a, b) => {
  if (a == null && b == null) return 0;
  if (a == null) return -1;          // 原 -Infinity 语义：空值恒排最前
  if (b == null) return 1;
  if (typeof a === 'number' && typeof b === 'number') return a - b;
  return String(a).localeCompare(String(b), 'zh');
};
```

- 验证：Edge headless 逐视图点击受影响表头，断言首行值与升降序一致（升/降各一次）
