# 买卖区间分析功能 · 设计方案

> 状态：设计定稿（用户已确认 4 个决策点），待按 S1→S8 分步实施
> 决策确认：① 指数/ETF 用"股息率反推分位 + 价格分位"替代 PE/PB 历史；② 接受 D 短期稳定反推假设（季度调样后重算 D）；③ 回测并行不阻塞上线；④ 权重三档预设（稳健/均衡/进取）
> 实施原则：**先简单后复杂，功能一步一步往上加**，每步独立可验证、可提交，确认后再进下一步

## 一、数据盘点（现有资产能支撑什么）

| 数据 | 指数(11) | ETF(11) | 股票(20) |
|---|---|---|---|
| 日线 OHLCV 全历史 | ✓ | ✓ | ✓（不复权+逐日指标） |
| 30/60/90日涨跌 | ✓ | ✓ | ✓ |
| **成分加权股息率快照** | ✓（_成分股汇总.json） | ✓（components.json） | ✓（逐日 dy 序列） |
| **PE-TTM/PB/PEG/ROE 历史序列** | ✗ 无 | ✗ 无 | ✓（逐日估值） |
| 净值/折溢价 | ✗ | ✓（nav/acc_nav） | ✗ |
| 成交额 | 腾讯5只无 | ✓（估算） | ✓ |

**核心约束**：指数/ETF 没有估值历史序列 → 无法做 PE 分位。红利指数的天然锚是**股息率**，可反推：

> **关键洞察**：`股息率_t = 当前成分加权股息总额 D ÷ 收盘价_t`（D 短期稳定：成分不换、分红不变，只随价格波动）。用"当前股息率快照 × 当前点位 ÷ 历史每日收盘"即可反推每只指数/ETF 的股息率历史序列 → 做股息率分位。
>
> 假设局限：成分调样、分红增长会使 D 漂移（季度调样后需重算 D）——用户已接受。

## 二、总体架构

```
cache/指数|ETF|股票_*.json ─┐
components.json(加权dy快照) ─┼→ _gen_analysis.py → web/data/analysis.json（因子分位+点位锚+三档权重）
股票指标文件(逐日dy/PE/PB) ─┘        │
                                    ├→ 前端本地算分（因子分位×权重 → 分数 → 区间），三档切换零延迟
_backtest_analysis.py（回测，并行）→ docs/回测报告.md
```

**关键设计决定**：
- analysis.json **只存因子分位，不存分数**——前端拿"分位 × 三档权重"本地算分，三档切换即时响应
- dy 曲线前端用已有 K 线数据重算（`dy_t = dy_now × close_now ÷ close_t`），不重复传序列

## 三、因子体系

### 体系 A：指数 / ETF（价格 + 股息率锚）

| 因子 | 计算 | 权重(稳/均/进) |
|---|---|---|
| **股息率分位** | dy 反推序列在近5年窗口分位（<25=贵，>75=便宜） | 40 / 30 / 20 |
| **价格分位** | close 在近5年窗口分位 | 30 / 30 / 30 |
| **趋势** | `50 + (MA60乖离÷15%)×50` 截断0-100；MA排列修正（close>MA60>MA200 多头+10，空头-10） | 20 / 20 / 30 |
| **情绪** | ETF=折溢价（close/nav-1，>+1%→100，<-1%→0）；指数=chg60 在5年窗口分位 | 10 / 20 / 20 |

### 体系 B：股票（估值分位全）

| 因子 | 计算 | 权重(稳/均/进) |
|---|---|---|
| **PE-TTM 分位** | 自身历史分位（<20%=便宜）；PE 为负（亏损期）取 100 | 20 / 20 / 15 |
| **PB 分位** | 自身历史分位 | 15 / 15 / 10 |
| **股息率分位** | 逐日 dy 序列分位 | 30 / 20 / 15 |
| **价格分位** | close 在近5年窗口分位 | 15 / 15 / 20 |
| **趋势** | 同体系A | 10 / 15 / 25 |
| **PEG** | <1 → 0（便宜）；1~2 线性；>2 → 100 | 10 / 15 / 15 |

> 权重逻辑：稳健更重股息率（红利本质），进取更重趋势（吃动量）。

### 统一口径
- 因子分位统一 0-100：**0=最便宜，100=最贵**
- 分位窗口 = 近 1250 交易日（5年），数据不足用全部

## 四、打分与区间映射

```
分数 = Σ(因子分位 × 权重)
```

| 分数 | 区间 | 操作建议 |
|---|---|---|
| ≤ 25 | 🔴 **买入区间** | 分批买入（股息率>75分位） |
| 25~45 | 🟠 逐步建仓区 | 定投/加码 |
| 45~65 | ⚪ 持有区 | 不动 |
| 65~80 | 🟢 逐步卖出区 | 分批止盈 |
| ≥ 80 | 🟢 **卖出区间** | 清仓/大比例减仓 |

## 五、点位锚（具体买入/卖出点位）

- **买入锚** = `D ÷ dy90分位`；**卖出锚** = `D ÷ dy10分位`（与因子同窗口，近5年）
- 例：某指数当前点位 5800、加权dy 5.0%、历史dy 90分位 6.5% → 买入锚 ≈ 5800×5.0/6.5 ≈ **4462 点**，跌到附近即进入买入区间

## 七、实施步骤（简单→复杂，每步独立提交）

### S1：股息率反推序列 + 分位（数据基石，纯后端）
- **做什么**：`_gen_analysis.py` 第一步——11 指数/11 ETF 反推 dy 序列并算分位；20 股票直接用现有逐日 dy
  - `dy0` = 成分加权股息率快照（指数用 `_成分股汇总.json` 的 w×dy 加权，无权重成分用简单平均；ETF 用 components.json 同口径；与官方快照核对误差 <0.3% 即通过）
  - `D = close_now × dy0`；`dy_t = D ÷ close_t`（ETF 优先净值 nav，缺失用 close）
- **产出**：`cache/analysis_dy_*.json` + 控制台对照表（每标的：dy0、当前 dy、5年 10/50/90 分位）
- **验收**：抽查 000922（官方快照 vs 加权计算）、中证红利与红利ETF 510880 的 dy 序列形态合理（同源指数应贴近）；无前端改动

### S2：回测验证（并行，独立脚本）
- **做什么**：`_backtest_analysis.py`——dy 上穿90分位=买、下穿10分位=卖（持仓状态机），统计信号后 1/3/6/12 个月收益、胜率、最大回撤 vs 全期随机买入基准；参数敏感性 p85/90/95 各跑一遍
- **产出**：`docs/回测报告.md`（每标的一张表）
- **验收**：胜率/超额为正 → 因子权重可行；系统性失效则回 S3 调权重或放弃（S2 结果决定 S3 权重表）

### S3：因子打分 v1（固定权重=均衡档）
- **做什么**：补齐全部因子分位，输出 analysis.json v1（date、by_code：各因子分位、均衡档分数、band）
- **验收**：控制台打印 42 标的分数表，人工核对排序直觉

### S4：三档权重参数化
- **做什么**：稳健/均衡/进取三档权重表写入 analysis.json，数据层不再算分
- **产出**：analysis.json v2（presets + 因子分位，无 scores）
- **验收**：三档分数差异符合直觉（稳健档对 dy 分位更敏感）

### S5：点位锚
- **做什么**：买入锚/卖出锚写入 analysis.json + 控制台打印"现价 → 买入锚（距离 -x%）→ 卖出锚（距离 +x%）"
- **验收**：对照《红利介绍.md》历史股息率区间人工复核

### S6：前端 v1——「区间分析」tab（指数/ETF 先行）
- **做什么**：详情页 tab 改"图表 | 成分股 | 区间分析"；新面板：分数仪表盘（默认均衡档）+ 区间标签（买入=红系/建仓=橙/持有=灰/止盈与卖出=绿系，A股惯例）+ 当前 dy 与分位 + 因子明细表（因子名/当前值/分位/权重/得分进度条）+ 三档切换按钮组
- **验收**：切三档分数联动；因子表数字与 S3 控制台一致

### S7：前端 v2——区间带叠加 + dy 曲线
- **做什么**：K 线主图叠加 buy_anchor（红虚线）/sell_anchor（绿虚线）水平带，图例标注距离%；dy 曲线副图（前端用已有 K 线重算 `dy_t = dy_now×close_now/close_t`）+ 当前值 + 90/10 分位线
- **验收**：视觉核对锚线与历史触底/见顶位置吻合（如 2024 年低点应接近买入锚）

### S8：股票板块接入 + 回测页 + 流程集成（收尾）
- **做什么**：股票视图加"区间分析"tab（体系B）；前端回测报告入口（S2 的 md 渲染成页）；`_gen_analysis.py` 挂入 update.py 选项 7；全量回归 + git 提交
- **验收**：42 标的全部有区间分析；`python update.py` 7 一键含分析数据
